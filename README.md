# CS-250-Software-Development-Lifecycle
SNHU Travel project retrospective and reflections on user stories and Agile development

This repository contains my Sprint Review and Retrospective for the
SNHU Travel project. Throughout the course, I worked in different
Scrum roles and practiced writing user stories, creating test cases,
and updating a Java program when requirements changed.

## How do I interpret user needs and implement them into a program? How does creating user stories help with this?

I start by understanding what users want to do and asking questions
when their requests are unclear. User stories help explain what a
feature should accomplish and why someone would use it. For example,
the maximum-price story for SNHU Travel connected a price limit to
the user’s need to stay within a budget. Acceptance criteria helped
define how the feature should work and what I needed to test.

## How do I approach developing programs? What Agile processes do I hope to incorporate into my future development work?

I break the work into smaller parts so I can check my progress and
catch problems along the way. In future projects, I want to use a
prioritized backlog and clear acceptance criteria instead of trying
to figure everything out while coding. I also want to test regularly
and review what I could do better. Updating the SNHU Travel slideshow
showed me how useful it is to have working software that I can revise
when requirements change.

## What does it mean to be a good team member in software development?

A good team member follows through on their work and lets others
know when something is hindering their progress. It also means
listening to feedback, asking questions, and helping teammates when
needed. Working through the different Scrum roles showed me how
one unclear requirement can affect both development and testing.
